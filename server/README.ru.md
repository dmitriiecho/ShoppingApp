# Сервер ShoppingApp

[English](README.md)

Небольшой сервер на Ktor для приложения: каталог, промокоды и проверка корзины.

- **Адрес:** `http://2.56.204.151:8080/` (домена нет, поэтому нет и HTTPS).
- **Сборка:** отдельная Gradle-сборка, в `settings.gradle.kts` приложения не подключена.
- **Форматы** совпадают с DTO приложения: `ProductDTO` в `feature/catalog`, `PromoCodeDTO` в `feature/promo`, `CartValidationDTO.kt` в `:shared:data`.

## API

| Запрос | Что отдаёт |
|---|---|
| `GET /products` | Страницу каталога |
| `GET /products/{id}` | Один товар |
| `GET /promo-codes` | Все промокоды |
| `GET /promo-codes/{code}` | Один промокод |
| `GET /images/{file}` | Картинку товара |
| `POST /cart/validate` | Чем корзина расходится с каталогом |

У каждого запроса и ответа, на которые опирается приложение, есть образец в [`api-samples/`](api-samples/), а `requests.json` там хранит адрес каждого запроса. Тесты сервера проверяют, что он отвечает именно так, а тесты приложения читают те же файлы, поэтому изменение формата или адреса с одной стороны роняет тесты этой стороны.

### `GET /products`

| Параметр | Значение |
|---|---|
| `query` | Поиск по названию. Регистр и пробелы по краям не важны; пустой отдаёт весь каталог. |
| `page` | Номер страницы, с 1. |
| `pageSize` | От 1 до 100. |

На неправильные `page` или `pageSize` ответ 400. Товары идут в порядке `products.json`.

```json
{
  "products": [
    {
      "id": "1",
      "name": "Wireless Headphones",
      "price": 14999,
      "imageUrl": "http://2.56.204.151:8080/images/1.png",
      "description": "Over-ear wireless headphones…",
      "availableQuantity": 3
    }
  ],
  "endReached": false
}
```

- `price` в центах США: `14999` — это $149.99.
- `availableQuantity` — сколько штук можно заказать; `0` — товар закончился.

### `GET /products/{id}`

Один товар в том же формате или 404.

### `GET /promo-codes`

Все коды в порядке `promo-codes.json`. Приложение показывает их подсказкой на экране промокода.

```json
[{"code": "SALE10", "discountPercent": 10}, {"code": "SALE25", "discountPercent": 25}]
```

### `GET /promo-codes/{code}`

Один код или 404. Регистр и пробелы по краям не важны: на `sale10` вернётся `SALE10`, как код записан в файле.

```json
{"code": "SALE10", "discountPercent": 10}
```

### `GET /images/{file}`

Файл из `data/images/`. Сюда указывает `imageUrl` товара.

### `POST /cart/validate`

Проверка корзины перед оформлением заказа. `promoCode` можно не передавать.

```json
{
  "items": [{"productId": "1", "price": 7999, "quantity": 2}],
  "promoCode": "SALE10"
}
```

Ответ:

```json
{
  "issues": [{"type": "priceChanged", "productId": "1", "newPrice": 8999}],
  "promoCodeValid": true
}
```

`issues` пуст, если корзина совпадает с каталогом. У позиции бывают такие проблемы:

| `type` | Когда | Доп. поле |
|---|---|---|
| `unavailable` | Товар закончился или его нет в каталоге | — |
| `priceChanged` | Цена не совпадает с каталогом | `newPrice` |
| `notEnoughStock` | В корзине больше, чем `availableQuantity` | `availableQuantity` |

- У `unavailable` других проблем не бывает.
- Цена и остаток проверяются независимо: у одного товара могут прийти и `priceChanged`, и `notEnoughStock`.
- `promoCodeValid` — `false`, если присланного кода больше нет в `promo-codes.json`, и `true`, если код не прислан.
- На тело не того формата ответ 400.

## Данные

| Файл | Что в нём |
|---|---|
| `data/products.json` | Товары |
| `data/promo-codes.json` | Промокоды |
| `data/images/` | Картинки товаров |

JSON читается один раз при запуске: после правки нужен `./deploy.sh`. Картинки читаются на каждый запрос.

### Правила

- **Товары не удаляются**: закончившемуся ставится `"availableQuantity": 0`. На это рассчитывает постраничная загрузка в приложении (`ProductApi` в `feature/catalog`).
- **Новый товар** получает id больше существующих и дописывается в конец файла.
- **Цены** в долларах США, целым числом центов: `"price": 14999` — это $149.99.
- **`availableQuantity`** не бывает отрицательным.
- **`discountPercent`** от 1 до 100 и не меняется: для другой скидки заводят новый код.
- **Удалённый промокод** перестаёт действовать: приложение, где он применён, узнает об этом при проверке корзины.

Сервер не запустится, если id или коды повторяются, в JSON ошибка или неизвестное поле, а тесты поймают это ещё при сборке.

### Товары, на которые рассчитывают настройки

В настройках приложения есть пункты, которые кладут в корзину копию товара, чтобы показать проблему в корзине (use case'ы в `feature/settings`). У этих товаров значения должны сохраняться, иначе корзина покажет другую проблему.

| Товар | Должно сохраняться | Пункт настроек | Что кладёт в корзину |
|---|---|---|---|
| `16` Hoodie | остаток 0 | Добавить закончившийся товар в корзину | 1 шт. |
| `48` Laundry Basket | остаток 1–9, цена 4699 | Добавить товар сверх остатка | 10 шт. |
| `40` Cutting Board | остаток больше 0, цена не 4900 | Добавить товар со старой ценой | 1 шт. по 4900 |
| `32` Notebook | остаток 1–9, цена не 995 | Добавить товар с двумя изменениями | 10 шт. по 995 |

`DataFilesTest` отправляет эти корзины серверу на настоящем `data/products.json` и проверяет, что каждая по-прежнему получает ровно своё изменение, так что `./gradlew test` (и CI) падает, если это нарушено.

## Запуск

```sh
./gradlew test            # тесты, в том числе чтение файлов из data/
./gradlew run             # запустить локально на порту 8080 с data/
./gradlew spotlessCheck   # стиль кода (правила в .editorconfig в корне); spotlessApply исправляет
./deploy.sh               # тесты, сборка и перезапуск сервера на этой машине
```

На машине сервер работает как пользовательский systemd-сервис `shoppingapp-server` из копии в `~/server/shoppingapp`, поэтому новая сборка не трогает запущенную версию. После перезагрузки он стартует сам, sudo не нужен.

```sh
journalctl --user -u shoppingapp-server -f        # логи, в том числе каждый запрос
systemctl --user status shoppingapp-server        # запущен ли (а также stop, restart)
```
