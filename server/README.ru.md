# Сервер ShoppingApp

[English version](README.md)

Небольшой сервер на Ktor для приложения: отдаёт каталог и промокоды и проверяет корзину.

- **Адрес:** `http://2.56.204.151:8080/` (домена нет, поэтому нет и HTTPS).
- **Сборка:** отдельная Gradle-сборка, которая не подключена в `settings.gradle.kts` приложения.
- **Форматы** совпадают с DTO приложения: `ProductDTO` в `feature/catalog`, `PromoCodeDTO` в `feature/promo`, `CartValidationDTO.kt` в `:shared:data`.

## API

| Запрос | Что отдаёт |
|---|---|
| `GET /products` | Страницу каталога |
| `GET /products/{id}` | Один товар |
| `GET /promo-codes` | Все промокоды |
| `GET /promo-codes/{code}` | Один промокод |
| `GET /images/{file}` | Картинку товара |
| `POST /cart/validate` | Чем корзина отличается от каталога |

У каждого запроса и ответа, на которые опирается приложение, есть образец в [`api-samples/`](api-samples/), а в лежащем там же `requests.json` записан адрес каждого запроса. Тесты сервера проверяют, что он отвечает в точности как в образцах, а тесты приложения читают те же файлы, поэтому если поменять формат или адрес на одной стороне, упадут тесты этой стороны.

### `GET /products`

| Параметр | Значение |
|---|---|
| `query` | Поиск по названию. Регистр и пробелы в начале и в конце не учитываются; пустой запрос возвращает весь каталог. |
| `page` | Номер страницы, начиная с 1. |
| `pageSize` | От 1 до 100. |

На некорректные `page` или `pageSize` сервер отвечает 400. Товары возвращаются в том порядке, в каком записаны в `products.json`.

```json
{
  "products": [
    {
      "id": "1",
      "name": "Wireless Headphones",
      "price": 14999,
      "imageUrl": "http://2.56.204.151:8080/images/1.png",
      "description": "Over-ear wireless headphones…",
      "availableQuantity": 3
    }
  ],
  "endReached": false
}
```

- `price` в центах США: `14999` — это $149.99.
- `availableQuantity` — сколько штук можно заказать; `0` значит, что товар закончился.

### `GET /products/{id}`

Один товар в том же формате или 404.

### `GET /promo-codes`

Все коды в том порядке, в каком они записаны в `promo-codes.json`. Приложение показывает их как подсказку на экране промокода.

```json
[{"code": "SALE10", "discountPercent": 10}, {"code": "SALE25", "discountPercent": 25}]
```

### `GET /promo-codes/{code}`

Один код или 404. Регистр и пробелы в начале и в конце не учитываются: на `sale10` вернётся `SALE10` — в том виде, в каком код записан в файле.

```json
{"code": "SALE10", "discountPercent": 10}
```

### `GET /images/{file}`

Файл из `data/images/`. Сюда указывает `imageUrl` товара, который складывается из адреса сервера (`PUBLIC_URL`), `/images/` и поля `image` товара.

### `POST /cart/validate`

Проверка корзины перед оформлением заказа. `promoCode` можно не передавать.

```json
{
  "items": [{"productId": "1", "price": 7999, "quantity": 2}],
  "promoCode": "SALE10"
}
```

Ответ:

```json
{
  "issues": [{"type": "priceChanged", "productId": "1", "newPrice": 8999}],
  "promoCodeValid": true
}
```

Если корзина совпадает с каталогом, `issues` пуст. У позиции бывают такие проблемы:

| `type` | Когда | Доп. поле |
|---|---|---|
| `unavailable` | Товар закончился или его нет в каталоге | — |
| `priceChanged` | Цена не совпадает с каталогом | `newPrice` |
| `notEnoughStock` | В корзине больше, чем `availableQuantity` | `availableQuantity` |

- У позиции с `unavailable` других проблем не бывает.
- Цена и остаток проверяются независимо, поэтому у одного товара могут быть одновременно `priceChanged` и `notEnoughStock`.
- `promoCodeValid` равен `false`, если присланного кода больше нет в `promo-codes.json`, и `true`, если код не передан.
- Если тело запроса в неверном формате или `quantity` меньше 1, сервер отвечает 400.

## Данные

| Файл | Что в нём |
|---|---|
| `data/products.json` | Товары |
| `data/promo-codes.json` | Промокоды |
| `data/images/` | Картинки товаров, `<id>.png` |

JSON-файлы читаются один раз при запуске, поэтому после их правки нужно выполнить `./deploy.sh`. Картинки читаются при каждом запросе.

### Правила

- **Товары не удаляются**: если товар закончился, ему ставится `"availableQuantity": 0`. На это рассчитывает постраничная загрузка в приложении (`ProductApi` в `feature/catalog`).
- **Новый товар** получает id больше всех существующих и дописывается в конец файла.
- **Цены** указываются в долларах США, целым числом центов: `"price": 14999` — это $149.99.
- **`availableQuantity`** не бывает отрицательным.
- **`discountPercent`** — от 1 до 100 и никогда не меняется: для другой скидки заводят новый код.
- **Удалённый промокод** перестаёт действовать: приложение, в котором он уже применён, узнает об этом при проверке корзины.
- **`image`** — имя файла в `data/images/`, `<id>.png`. Полный адрес не хранится, потому что он зависит от того, где запущен сервер.
- **У товара `3` (USB-C Hub) нет файла картинки** — так задумано: на нём видно, что показывает приложение, когда картинка не загрузилась. У всех остальных товаров есть свой `<id>.png`; `DataFilesTest` проверяет и то, и другое.

Сервер не запустится, если id или коды повторяются, в JSON есть ошибка или неизвестное поле, а тесты поймают такие проблемы ещё при сборке.

### Товары, на которые рассчитывают настройки

В настройках приложения есть пункты, которые кладут товар в корзину, чтобы показать определённую проблему (use case'ы в `feature/settings`). Значения у этих товаров должны оставаться прежними, иначе корзина покажет другую проблему.

| Товар | Должно сохраняться | Пункт настроек | Что кладёт в корзину |
|---|---|---|---|
| `16` Hoodie | остаток 0 | Добавить закончившийся товар в корзину | 1 шт. |
| `48` Laundry Basket | остаток 1–9, цена 4699 | Добавить товар сверх остатка | 10 шт. |
| `40` Cutting Board | остаток больше 0, цена не 4900 | Добавить товар со старой ценой | 1 шт. по 4900 |
| `32` Notebook | остаток 1–9, цена не 995 | Добавить товар с двумя изменениями | 10 шт. по 995 |

`DataFilesTest` отправляет эти корзины серверу, запущенному на настоящем `data/products.json`, и проверяет, что каждая по-прежнему получает ровно свою проблему, поэтому `./gradlew test` (и CI) упадёт, если что-то из этого нарушится.

## Запуск

```sh
./gradlew test            # запустить тесты, в том числе чтение файлов из data/
./gradlew run             # запустить локально на порту 8080 с data/; адреса картинок начинаются с http://localhost:8080
./gradlew spotlessCheck   # проверить стиль кода (правила в .editorconfig в корне); spotlessApply исправляет
./deploy.sh               # прогнать тесты, собрать и перезапустить сервер на этой машине
```

`deploy.sh` передаёт серверу `PORT`, `DATA_DIR` и `PUBLIC_URL` — адрес, по которому к нему обращается приложение (`ServerConfig.BASE_URL` в `core/config`).

На машине сервер работает как пользовательский systemd-сервис `shoppingapp-server` и запускается из копии в `~/server/shoppingapp`, поэтому новая сборка не затрагивает запущенную версию. После перезагрузки он стартует сам, sudo для этого не нужен.

```sh
journalctl --user -u shoppingapp-server -f        # логи, в том числе каждый запрос
systemctl --user status shoppingapp-server        # проверить, запущен ли (а также stop, restart)
```
