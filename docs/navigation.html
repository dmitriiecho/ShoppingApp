Как устроена навигация

Приложение собирает один корневой NavHost в модуле :app. Фичи не знают друг о друге: каждая отдаёт свой граф и набор колбэков, а приложение склеивает переходы.

Navigation Compose 2.9.6 kotlinx.serialization routes single activity feature graphs

1. Принципы

Один NavController

Создаётся в AppNavHost через rememberNavController() и живёт на весь процесс. Отдельных хостов на таб нет.

Вложенные графы вместо XML

Каждый экран — @Serializable Kotlin-тип. Графы объявляются navigation<Route> { }, экраны — composable<Route> { }.

Фича не импортирует другую фичу

Каталог не знает про корзину. Переход «открой корзину» — лямбда onOpenCart, которую подставляет :app.

Табы сохраняют стек

Переключение Каталог ↔ Корзина идёт с saveState / restoreState. Детали товара, открытые в каталоге, не теряются, если уйти в корзину и вернуться.

2. Кто чем владеет

Навигационные типы и билдеры живут в фичах. Приложение только монтирует их в корневой хост и решает, куда ведёт колбэк.

5. Нижние вкладки

AppBottomBar смотрит на currentDestination.hierarchy. Вкладка выбрана, если в предках есть CatalogTab или CartTab. Клик не делает navigate(screen), а вызывает отдельный хелпер: 

private fun NavHostController.navigateToBottomTab(route: Any) {
    navigate(route) {
        popUpTo(graph.findStartDestination().id) { saveState = true }
        launchSingleTop = true
        restoreState = true
    }
}
ФлагЗачем
popUpTo(startDestination) + saveState Не раздувать стек копиями табов. Состояние графа уходящей вкладки кладётся в Restoration.
launchSingleTop Повторный тап по уже выбранной вкладке не пушит её ещё раз.
restoreState Вернувшись в Каталог, пользователь снова видит Product Details, если уходил с него.
Отличие от колбэка onOpenCart. В AppNavHost каталог открывает корзину так: navigate(CartRoutes.Graph) — без saveState/restoreState. Это переход к графу корзины, а не «переключить таб как в BottomBar». Если понадобится одинаковое поведение, колбэк стоит вести в navigateToBottomTab(CartTab).

6. Type-safe маршруты

Каждый маршрут — Kotlin-класс с @Serializable. Navigation Compose сериализует его в строку back stack и обратно. Аргументы становятся полями класса, а не «магическими» query-ключами в XML.

Без аргументов 
@Serializable
data object ProductList
С аргументами 
@Serializable
data class ProductDetails(
    override val productId: String,
    override val productName: String = "",
) : ProductDetailsRoute

Имя поля = ключ в SavedStateHandle. ViewModel деталей читает их так: 

private val productId = checkNotNull(savedStateHandle.get<String>("productId"))
private val productName = savedStateHandle.get<String>("productName").orEmpty()

productName передаётся сразу при навигации, чтобы тулбар показал название до ответа сети. Пустой default нужен диплинку, у которого может быть только id.

Видимость internal у экранов фичи (ProductList, Cart, Checkout) не даёт приложению навигировать «мимо» публичного Graph-маршрута. Снаружи виден граф, не лист.

7. Изоляция фич: колбэки вместо прямых navigate

Фича объявляет XxxNavigationScope и extension на NavGraphBuilder. Снаружи это выглядит как DSL: 

catalog.catalogGraph(
    navController = navController,
    onClose = { },
    onOpenCart = { navController.navigate(CartRoutes.Graph) },
)

8. Два входа в детали товара

Контракт экрана вынесен в интерфейс, а не в конкретный route-класс: 

interface ProductDetailsRoute {
    val productId: String
    val productName: String
}
из каталога

CatalogRoutes.ProductDetails лежит внутри CatalogRoutes.Graph. Back возвращает к списку той же вкладки.

из корзины

CustomProductRoute объявлен в :app и регистрируется catalog.productDetailsScreen<CustomProductRoute>() уже внутри CartTab.

flowchart LR
  List[ProductList] -->|navigate ProductDetails| DetCatalog[ProductDetailsScreen
route = CatalogRoutes.ProductDetails]
  Cart[CartScreen] -->|navigate CustomProductRoute| DetCart[ProductDetailsScreen
route = CustomProductRoute]

  DetCatalog -.->|SavedStateHandle productId/name| VM1[ProductDetailsViewModel]
  DetCart -.->|те же ключи полей| VM2[ProductDetailsViewModel]

Дженерик-хелпер в каталоге: 

inline fun <reified T> CatalogNavigationScope.productDetailsScreen(
    noinline onBack: () -> Unit,
) where T : Any, T : ProductDetailsRoute {
    builder.composable<T> {
        ProductDetailsScreen(onBack = onBack)
    }
}

ViewModel не знает, с какого таба его открыли: ему достаточно одинаковых имён полей. Hilt создаёт отдельный экземпляр на каждый back stack entry.

9. Промокод: граф с аргументом и возврат результата

Это самый сложный поток. Промокод — не «просто экран», а вложенный граф с аргументом resultKey. Ключ нужен, чтобы корзина знала, куда в SavedStateHandle ждать ответ. 

sequenceDiagram
  participant Cart as Cart composable
  participant App as AppNavHost
  participant Promo as PromoRoutes.Graph
  participant Screen as PromoCodeScreen

  Cart->>App: onOpenPromo("cart_promo_result")
  App->>Promo: navigate(Graph(resultKey))
  Screen->>Screen: parentEntry.toRoute<Graph>().resultKey
  Screen->>App: onCloseWithResult(resultKey, PromoCode)
  App->>App: popBackStack<Promo Graph>(inclusive = true)
  App->>Cart: currentBackStackEntry.savedStateHandle[resultKey] = CartPromoResult
  Cart->>Cart: collect getStateFlow(resultKey)
  Cart->>Cart: viewModel.onPromoApplied(result.toPromoCode())
  Cart->>Cart: remove(resultKey)
  Cart->>Cart: CartRepository.applyPromoCode → Room

Почему resultKey на графе, а не на экране

PromoCodeScreen читает ключ с родительского back stack entry: 

val parentEntry = remember(entry) {
    navController.getBackStackEntry<PromoRoutes.Graph>()
}
val resultKey = parentEntry.toRoute<PromoRoutes.Graph>().resultKey

Так ключ принадлежит графу целиком. Если внутри промо позже появятся шаги (ввод → подтверждение), все они увидят тот же resultKey.

Контракт результата

  • Фича promo сначала проверяет код через PromoApi (в debug — FakePromoApi) и только потом отдаёт доменную модель PromoCode (код и процент скидки) — обычный data class без обёрток.
  • App мапит его в CartPromoResult(promoCode, discountPercent), который Parcelable, потому что SavedStateHandle переживает смерть процесса.
  • Корзина слушает entry.savedStateHandle.getStateFlow<CartPromoResult?>(KEY, null) и после обработки удаляет значение, чтобы не применить промокод повторно при recomposition.
  • Обработка — это сохранение через CartRepository.applyPromoCode в Room, рядом с товарами. Промокод становится частью модели Cart, поэтому корзина и checkout считают одну и ту же скидку, и она переживает перезапуск приложения. Оформление заказа (clear()) удаляет товары и промокод в одной транзакции.

Фича promo не знает о корзине: она только проверяет код и возвращает результат. Что с ним делать, решает получатель.

Закрытие крестиком идёт через onClose — тот же popBackStack<Promo Graph>(inclusive = true), но без записи в Handle.

10. Checkout — sibling, не вкладка

Граф оформления регистрируется на корне NavHost, рядом с табами, а не внутри CartTab: 

checkout.checkoutGraph(
    navController = navController,
    onClose = {
        navController.popBackStack<CheckoutRoutes.Graph>(inclusive = true)
    },
)

Навигация из корзины: navigate(CheckoutRoutes.Graph). Back / Close снимает весь граф целиком (inclusive = true), пользователь возвращается туда, откуда открыл checkout — обычно на Cart.

Нижняя панель скрыта, потому что в hierarchy текущего destination нет ни CatalogTab, ни CartTab. Это правило общее: любой будущий full-screen flow достаточно повесить соседом табов.

11. Диплинки

База задана в core/config: DeepLinkConfig.BASE_URI = "https://shopping.example.com". Фичи сами вешают navDeepLink<Route>(basePath = ...). Activity ловит https-интенты в манифесте.

URLКуда попадаетГде объявлен
https://shopping.example.com/catalog ProductList CatalogNavigation + Manifest pathPrefix /catalog
https://shopping.example.com/product/{productId} ProductDetails (каталожный route) navDeepLink<CatalogRoutes.ProductDetails>, pathPrefix /product
https://shopping.example.com/cart Cart CartNavigation + pathPrefix /cart

Promo и Checkout диплинков не имеют. Имя товара в диплинке продукта опционально (productName = ""): тулбар покажет «Товар», пока не загрузится сущность.

android:autoVerify="true" стоит на VIEW-фильтре. Для боевого App Links нужна Digital Asset Links на домене shopping.example.com. Сейчас это учебный хост.

Краткая шпаргалка

  1. Хотите новый экран внутри фичи — добавьте @Serializable тип и composable в её Navigation.kt.
  2. Хотите вход снаружи — оставьте Graph публичным, экраны internal.
  3. Хотите переход в другую фичу — добавьте колбэк, реализуйте его только в AppNavHost.
  4. Хотите сохранить стек таба — переключайтесь через navigateToBottomTab.
  5. Хотите спрятать табы — вешайте граф соседом CatalogTab/CartTab, как Checkout.
  6. Хотите вернуть результат — ключ на родительском Graph + Parcelable в SavedStateHandle предыдущего entry.
Сгенерировано по текущему коду ShoppingAppV2. Источник правды — Kotlin-графы в AppNavHost и feature-модулях, не этот HTML.
